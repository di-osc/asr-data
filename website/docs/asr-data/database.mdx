[`AudioDB`](/asr-data/api#audio-db) 使用一个 SQLite 文件持久化
[`Audio`](/asr-data/api#audio)。数据库保存音频来源、`AudioInfo`、
timeline、annotation 和业务元数据，不复制解码后的浮点样本。

右侧 Example 按页面顺序连续执行，后面的示例会直接使用前面创建的数据库和文档。

## 打开数据库 {id="open"}

Rust 示例：

```rust
use asr_data::{AudioDb, AudioDbMode};

fn main() -> anyhow::Result<()> {
    let db = AudioDb::create("dataset.vasr")?;
    drop(db);
    let _db = AudioDb::open("dataset.vasr", AudioDbMode::ReadOnly)?;
    Ok(())
}
```

使用 `AudioDB.create(path)` 创建新数据库，使用 `AudioDB.open(path)` 打开已有
数据库。两个入口不会互相兜底，因此路径写错时不会意外创建空数据库。

> #### Python Example
>
> ```python
> from tempfile import TemporaryDirectory
>
> from asr_data import AudioDB
>
> directory = TemporaryDirectory()
> path = f"{directory.name}/dataset.db"
> db = AudioDB.create(path)
> opened = AudioDB.open(path)
> ```

> #### Rust Example
>
> ```rust
> use asr_data::{AudioDb, AudioDbMode};
>
> fn main() -> anyhow::Result<()> {
>     let path = "dataset.vasr";
>     let db = AudioDb::create(path)?;
>     drop(db);
>     let _db = AudioDb::open(path, AudioDbMode::ReadOnly)?;
>     Ok(())
> }
> ```

`create()` 在文件已经存在时抛出 `FileExistsError`；`open()` 在文件不存在时抛出
`FileNotFoundError`。推荐使用 `.db` 后缀，以便工具和使用者识别文件类型。数据库包含专用 SQLite
application ID 和 schema version。当前仅接受 schema v11；打开普通 SQLite 文件或其
他版本时会立即报错，而不是尝试迁移或按错误结构读写。

一个数据库可以包含大量 [`Audio`](/asr-data/api#audio)，但每个文档 ID 必须
唯一。路径只决定数据库文件位置，不会改变
[`AudioSource`](/asr-data/api#audio-source) 中保存的本地路径或 URL。

`AudioInfo` 与文档一起持久化。因此读取数据库记录时不会重新打开本地文件或请求
URL；即使原始来源暂时不可用，仍然可以读取采样率、声道、帧数、时长和全部标注。

## 增删改查 {id="crud"}

[`AudioDB`](/asr-data/api#audio-db) 同时提供显式方法和类似字典的读取协议。插入、
更新和删除都以 [`Audio`](/asr-data/api#audio) ID 为记录主键。

> #### Python Example
>
> ```python
> from asr_data import Audio, AudioSource
>
> URL = "https://deepasset.oss-cn-beijing.aliyuncs.com/example.wav"
> doc = AudioSource.from_url(URL).load(id="call-001")
> doc.metadata["split"] = "train"
>
> # 增
> db.insert(doc)
> # 查
> loaded = db["call-001"]
> print(loaded.id, loaded.metadata)
> # 改
> loaded.metadata["checked"] = True
> changed = db.update(loaded)
> # 删
> deleted = db.delete("call-001")
>
> print(changed, deleted)
> db.insert(loaded)  # 供后续示例继续使用
> ```

> #### Rust Example
>
> ```rust
> use asr_data::{Audio, AudioDb, AudioSource};
>
> fn main() -> anyhow::Result<()> {
>     let db = AudioDb::create("dataset.vasr")?;
>     let audio = Audio::with_id(
>         "call-001",
>         AudioSource::from_url("https://deepasset.oss-cn-beijing.aliyuncs.com/example.wav"),
>     )?;
>     db.insert(&audio)?;
>     let loaded = db.get("call-001")?.unwrap();
>     println!("{}", loaded.id);
>     db.delete("call-001")?;
>     Ok(())
> }
> ```

| 操作                | 行为                                           |
| ------------------- | ---------------------------------------------- |
| `insert(doc)`       | 新增文档；ID 已存在时返回错误                  |
| `db[audio_id]`      | 按 ID 读取；不存在时抛出 `KeyError`            |
| `update(doc)`       | 只写入发生变化的部分；没有变化时返回 `False`   |
| `update_many(docs)` | 在单个 SQLite 事务中批量更新，返回实际更新数量 |
| `delete(audio_id)`  | 删除指定文档，返回是否确实删除                 |
| `audio_id in db`    | 判断 ID 是否存在                               |
| `len(db)`           | 返回文档数量                                   |
| `for doc in db`     | 通过内部游标懒加载全部文档                     |

`update()` 不执行隐式插入：目标 ID 必须已经存在。批量更新使用一个事务，任一写入
失败时不会留下只更新了一部分的数据。

数据库会为每条记录自动维护创建和修改时间。`insert()` 使用同一时刻初始化两个时间
；只有内容确实发生变化、`update()` 返回 `True` 时才更新修改时间。无变化的更新不
会改变时间，`update_many()` 中实际变化的记录使用同一个批次时间。

这两个时间属于数据库存储信息，不会写入 [`Audio`](/asr-data/api#audio) 或
`doc.metadata`，用户也不能手动设置。

### 查询与分页 {id="query"}

`query()` 可以同时按 metadata、时长、创建时间和修改时间筛选，并使用稳定的
Audio ID 游标分页。时间参数只接受带时区的 Python `datetime`，内部统一转换为
UTC Unix 毫秒。

> #### Python Example
>
> ```python
> from datetime import datetime, timedelta, timezone
>
> now = datetime.now(timezone.utc)
> page = db.query(
>     limit=10,
>     created_from=now - timedelta(days=7),
>     created_until=now,
>     updated_from=now - timedelta(hours=24),
>     metadata={"split": "train"},
> )
> print([item.id for item in page])
> ```

> #### Rust Example
>
> ```rust
> use asr_data::{AudioDb, AudioQuery};
>
> fn main() -> anyhow::Result<()> {
>     let db = AudioDb::open("dataset.vasr", asr_data::AudioDbMode::ReadOnly)?;
>     let mut query = AudioQuery::default();
>     query.limit = 10;
>     let page = db.query(&query)?;
>     for audio in page { println!("{}", audio.id); }
>     Ok(())
> }
> ```

时间范围统一使用半开区间：

```text
from <= timestamp < until
```

`created_from`、`created_until` 筛选创建时间，`updated_from`、`updated_until` 筛
选最后一次实际修改时间。四个条件都可以单独使用；传入无时区 `datetime` 或反向范围
会抛出 `ValueError`。

查询结果按 `audio_id` 排序。读取下一页时，将上一页最后一条记录的 ID 传给
`after`：

```python
next_page = db.query(limit=10, after=page[-1].id)
```

```rust
let mut next_query = AudioQuery::default();
next_query.limit = 10;
next_query.after = page.last().map(|audio| audio.id.clone());
let next_page = db.query(&next_query)?;
```

`after` 是游标而不是数字页码，因此即使数据库较大，也不需要跳过前面所有记录。
metadata 过滤要求存储值与查询值匹配，适合数据集 split、语言、来源和审核状态等结
构化字段。

## 数据集评测 {id="evaluation"}

数据库不提供通用 `eval()`；按任务使用 `eval_transcription()`、`eval_activity()`
或 `eval_speaker()`。三个方法都使用与 `query()` 相同的筛选条件，通过 Audio ID
游标自动读取全部匹配记录；`batch_size` 只控制单批读取量。

> #### Python Example
>
> ```python
> transcription = db.eval_transcription(
>     ["qwen-asr", "whisper"],
>     metadata={"split": "test"},
>     batch_size=100,
> )
> activity = db.eval_activity(
>     "silero-vad",
>     metadata={"split": "test"},
> )
>
> qwen = transcription["qwen-asr"]
> print(qwen.cer, qwen.coverage)
> print(activity["silero-vad"].f1)
> print(activity["silero-vad"].events["speech"].f1)
> ```

> #### Rust Example
>
> ```rust
> use asr_data::{AudioDb, AudioQuery, TimelineEvalConfig};
>
> fn main() -> anyhow::Result<()> {
>     let db = AudioDb::open("dataset.vasr", asr_data::AudioDbMode::ReadOnly)?;
>     let result = db.eval(&AudioQuery::default(), &TimelineEvalConfig::new())?;
>     println!("{}", result.transcription.len());
>     Ok(())
> }
> ```

不传 source 时自动发现该任务全部可评测来源。结果按 source 分组，并记录缺少
reference、缺少 prediction 和实际参与聚合的 timeline 数量。只读数据库同样可以
执行评测。

### 转写标准化

`eval_transcription()` 接受完整的内嵌 WeText 标准化配置：

```python
transcription = db.eval_transcription(
    "qwen-asr",
    metadata={"split": "test"},
)
print(transcription["qwen-asr"].cer)
```

```rust
let config = TimelineEvalConfig::new().with_transcription("qwen-asr");
let result = db.eval(&AudioQuery::default(), &config)?;
println!("{}", result.transcription["qwen-asr"].cer());
```

处理顺序为繁体转简体、TN tagger、普通或去儿化 verbalizer、全角转半角、去语气词、
去标点，最后执行 CER 的空白和标点清洗。五个选项默认均为 `True`；
`remove_interjections=True` 去除“嗯”“啊”和“呃”。`normalize=False` 时忽略其他
标准化选项。

### Activity 与 Speaker

```python
activity = db.eval_activity("silero-vad", metadata={"split": "test"})
speaker = db.eval_speaker("diarizer", metadata={"split": "test"})

print(activity["silero-vad"].f1)
print(speaker["diarizer"].der)
```

```rust
let activity = db.eval(
    &AudioQuery::default(),
    &TimelineEvalConfig::new().with_activity("silero-vad"),
)?;
let speaker = db.eval_speaker(&AudioQuery::default(), &["diarizer".to_owned()])?;
println!("{}", activity.activity["silero-vad"].f1());
println!("{}", speaker["diarizer"].der());
```

Speaker 评测在每条 timeline 内使用最佳一一映射消除 speaker label 命名差异，再累计
漏检、误检和说话人混淆的 speaker-time。DER 为三类错误时长之和除以 reference
speaker-time，不使用 collar；重叠说话按同时活跃的 speaker 数量计数。

## 数据库元数据 {id="metadata"}

数据库级 metadata 描述整个数据集，不属于任何一条 Audio，适合保存数据集版本、
标注批次或模型配置。

> #### Python Example
>
> ```python
> db.set_metadata("dataset_version", "2026-07")
> print(db.metadata_value("dataset_version"))
> print(db.metadata)
> ```

> #### Rust Example
>
> ```rust
> use asr_data::{AudioDb, AudioDbMode};
>
> fn main() -> anyhow::Result<()> {
>     let db = AudioDb::open("dataset.vasr", AudioDbMode::ReadWrite)?;
>     db.set_metadata("dataset_version", &serde_json::json!("2026-07"))?;
>     println!("{:?}", db.metadata("dataset_version")?);
>     Ok(())
> }
> ```

`set_metadata(key, value)` 新增或覆盖一个值，`metadata_value(key)` 查询单个值，
`delete_metadata(key)` 删除并返回是否存在。`db.metadata` 返回当前全部数据库级元
数据。

业务上只属于单条音频的信息应放在 `doc.metadata`；只有需要对整个数据库共享的信息
才应放在 `db.metadata`，这样查询和迁移时两者的作用域保持清晰。

## AudioDataset {id="audio-dataset"}

[`AudioDataset`](/asr-data/api#audio-dataset) 是公开的数据集抽象。它保存
`name`、`version` 和 `license` 三个只读身份字段，并通过 `.train`、`.val`、
`.test` 暴露三个可选且相互独立的 [`AudioDB`](/asr-data/api#audio-db)。数据集
切分由数据库文件决定，不再使用 `split` 字段，也不需要在数据库 metadata 中重复
保存数据集身份。

### 包装本地切分数据库 {id="audio-dataset-local"}

已有 AudioDB 可以按需包装为 AudioDataset，各自与数据集共享同一个数据库连接。
未提供的切分返回 `None`。本地低层构造不推断仓库身份，因此三个身份字段为空
字符串。

> #### Python Example
>
> ```python
> from pathlib import Path
> from tempfile import TemporaryDirectory
>
> from asr_data import AudioDB, AudioDataset
>
> directory = TemporaryDirectory()
> train = AudioDB.create(str(Path(directory.name) / "train.db"))
> test = AudioDB.create(str(Path(directory.name) / "test.db"))
> local_dataset = AudioDataset(train=train, test=test)
> print(len(local_dataset.train), local_dataset.val, len(local_dataset.test))
> ```

> #### Rust Example
>
> ```rust
> use asr_data::{AudioDataset, AudioDb};
>
> fn main() -> anyhow::Result<()> {
>     let train = AudioDb::create("train.vasr")?;
>     let test = AudioDb::create("test.vasr")?;
>     let dataset = AudioDataset::new(Some(("train.vasr".into(), train)), None,
>         Some(("test.vasr".into(), test)));
>     println!("{}", dataset.train().unwrap().len()?);
>     Ok(())
> }
> ```

每个切分都是完整的 AudioDB，因此在目标切分上直接使用查询、评测、索引和迭代
接口：

```python
page = local_dataset.train.query(limit=100)
result = local_dataset.test.eval(transcription="qwen-asr")
for audio in local_dataset.val:
    print(audio.id)
```

```rust
let page = dataset.train().unwrap().query(&Default::default())?;
for audio in page {
    println!("{}", audio.id);
}
```

### 从 ModelScope 加载 {id="audio-dataset-modelscope"}

ModelScope 仓库通过 Rust [`modelhub`](https://crates.io/crates/modelhub) crate
完整下载和缓存。快照中的 `train.db`、`val.db`、`test.db` 都是可选文件：存在时
只读打开，不存在时对应属性返回 `None`。

> #### Python Example
>
> ```python
> from asr_data import AudioDataset
>
> dataset = AudioDataset.from_modelscope(
>     "di-osc/aishell-1",
>     revision="v1.0.0",
> )
>
> print(dataset.name)     # di-osc/aishell-1
> print(dataset.version)  # v1.0.0
> print(dataset.license)  # README.md front matter 中的 license
>
> if dataset.test is not None:
>     for audio in dataset.test:
>         print(audio.id)
> ```

> #### Rust Example
>
> ```rust
> use asr_data::AudioDataset;
>
> #[tokio::main]
> async fn main() -> anyhow::Result<()> {
>     let dataset = AudioDataset::from_modelscope("di-osc/aishell-1", None, None).await?;
>     if let Some(test) = dataset.test() {
>         for audio in test { println!("{}", audio?.id); }
>     }
>     Ok(())
> }
> ```

`name` 直接使用 `repo_id`，`version` 使用实际加载的 revision，`license` 读取
同一 revision 下可选 `README.md` 的 YAML front matter `license` 字段；文件或
字段不存在时返回空字符串。数据库 metadata 不参与这些字段的计算。

`revision` 默认为 `master`。`cache_dir` 省略时使用 modelhub 的 ModelScope 默认
缓存目录，优先级为进程内覆盖、`MODELSCOPE_CACHE`、然后
`$HOME/.cache/modelscope`；也可以显式传入缓存根目录。缓存布局为：

```text
<cache>/datasets/<namespace--dataset>/snapshots/<revision>/
├── README.md
├── train.db
├── val.db
└── test.db
```

快照中的其他仓库文件也会下载；文件已存在时由 modelhub 直接复用。远端切分允许
读取、查询、评测和迭代，但插入、更新、删除或 metadata 写入会失败。

| 场景                                                 | 结果             |
| ---------------------------------------------------- | ---------------- |
| 仓库缺少某个切分数据库                               | 对应属性为 `None` |
| 整仓下载失败                                         | `AsrDataError`   |
| 已存在的切分文件不是受支持的 AudioDB/schema          | `AsrDataError`   |
| repo_id 或 revision 为空                             | `ValueError`     |
| README front matter 未闭合、license 重复或不是字符串 | `ValueError`     |

## 只读模式 {id="readonly"}

评测集、发布快照或其他不应被修改的数据库，可以使用 `read_only=True` 打开。

> #### Python Example
>
> ```python
> read_only = AudioDB.open(path, read_only=True)
> print(read_only["call-001"].id)
> ```

> #### Rust Example
>
> ```rust
> use asr_data::{AudioDb, AudioDbMode};
>
> fn main() -> anyhow::Result<()> {
>     let db = AudioDb::open("dataset.vasr", AudioDbMode::ReadOnly)?;
>     if let Some(audio) = db.get("call-001")? {
>         println!("{}", audio.id);
>     }
>     Ok(())
> }
> ```

只读模式要求文件已经存在且格式有效，读取、查询和迭代仍然可用；插入、更新、删除以
及数据库 metadata 写操作会失败。只读连接不会自动创建缺失文件。

需要删除记录时，应使用可写连接调用 `db.delete(audio_id)`。临时示例中的目录会在
Python 进程结束时自动清理；生产数据库应使用稳定的绝对路径并纳入备份策略。
