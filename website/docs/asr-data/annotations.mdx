标注以 [`Audio`](/asr-data/api#audio) 为文档边界，以[`Timeline`](/asr-data/api#timeline) 表达一个声道上的时间范围，并把参考真值与模型预测分别保存。音频样本负责“听到什么”，标注结构负责“在什么时间发生了什么”。
右侧 Example 按页面顺序连续执行，后面的示例会直接使用前面创建的变量。

## 音频 {id="document"}

[`Audio`](/asr-data/api#audio) 是音频、时间轴与标注的共同所有者。它把原始
[`AudioSource`](/asr-data/api#audio-source)、`info`、文档 ID、业务元数据、运行时
波形和多个声道 timeline 组织为一个对象。

> #### Python Example
>
> ```python
> from asr_data import AudioSource
>
> URL = "https://deepasset.oss-cn-beijing.aliyuncs.com/example.wav"
> audio = AudioSource.from_url(URL).load(id="example-001")
> audio.metadata["split"] = "train"
> print(audio.info.duration_ms, audio.timelines.keys())
> ```

> #### Rust Example
>
> ```rust
> use asr_data::{Audio, AudioSource};
>
> fn main() -> anyhow::Result<()> {
>     let audio = Audio::with_id(
>         "example-001",
>         AudioSource::from_url("https://deepasset.oss-cn-beijing.aliyuncs.com/example.wav"),
>     )?;
>     println!("{}", audio.info.duration_ms());
>     Ok(())
> }
> ```

数据库只保存 Audio 的可重建状态，不保存大块浮点样本。从数据库读取后，第一次访问
波形视图时会按来源恢复样本；这个缓存过程不属于公开数据模型，Audio 不暴露加载状态。

| 内容         | 用途                                             |
| ------------ | ------------------------------------------------ |
| `source`     | 可重新加载或流式读取的原始音频来源               |
| `info` | 不解码样本即可使用的格式、帧数和时长             |
| `id`         | 数据库主键和跨系统关联标识                       |
| `metadata`   | split、语言、来源、业务标签等文档级信息          |
| `timelines`  | 按声道保存的时间轴及其 reference/prediction 标注 |

业务系统应尽量提供唯一且固定的 `id`；省略时库会自动生成 ID。`metadata` 是普通字
典，不用于保存 annotation。

## 时间轴 {id="timeline"}

每个 [`Timeline`](/asr-data/api#timeline) 对应一个声道，并共享整条文档的
duration。 annotation 的所有时间范围都相对于所属 timeline 的起点。

> #### Python Example
>
> ```python
> timeline = audio.timeline("mono")
> print(timeline.duration_ms, audio.timelines.keys())
> ```

> #### Rust Example
>
> ```rust
> use asr_data::{Audio, AudioChannel, AudioSource};
>
> fn main() -> anyhow::Result<()> {
>     let audio = Audio::with_id(
>         "example-001",
>         AudioSource::from_url("https://deepasset.oss-cn-beijing.aliyuncs.com/example.wav"),
>     )?;
>     let timeline = audio.timeline(AudioChannel::Mono)?.unwrap();
>     println!("{}", timeline.duration_ms());
>     Ok(())
> }
> ```

创建 `Audio` 时会调用 `source.probe()`，保存 `info`，并根据声道自动创建
时间轴。单声道使用 `mono`；双声道使用 `left`、`right`；更多声道继续使用 `2`、
`3` 等编号。时间轴时长由帧数计算并向上取整到整数毫秒。

`ensure_timeline()` 仍可用于取回已有时间轴或补充派生声道；新时间轴默认复用
`info` 确定的文档时长。

| 操作                       | 行为                                     |
| -------------------------- | ---------------------------------------- |
| `ensure_timeline(channel)` | 获取已有时间轴，不存在时创建             |
| `timeline(channel)`        | 只查询，不存在时返回 `None`              |
| `remove_timeline(channel)` | 删除声道及其全部标注，返回是否确实删除   |
| `timelines`                | 返回以标准化声道名称为键的全部时间轴字典 |

`timeline()` 不会隐式创建对象，这样可以避免拼错声道名称时意外产生空 timeline。声
道既可以使用名称，也可以使用整数；内部会转换为稳定的字符串键。

### 卡片渲染 {id="rendering"}

[`Timeline`](/asr-data/api#timeline) 可以直接展示成一张卡片：终端里打印
`terminal_view()`，Jupyter 中由 `_repr_html_` 画出 HTML 卡片。Rust 通过
`Display`（`println!("{timeline}")`）或 `terminal_view()` 输出，Python 则是
`str(timeline)` 和 notebook 的富文本输出。

- 事件条用 `|--|` 端点标出范围，两端写起止时间，中间写角色与事件名：参考是
  `Reference · 🎙 Speech`，预测是 `Prediction · <source> · ...`。置信度不写在条上。
- 转写按句子和 token 各画一条时间轨道，和上方时间刻度共用同一套列坐标，因此上下
  按时间对齐；详情用 `├─` / `└─` 树形缩进展示说话人、语种、全文和句子。
- 一句话的 token 超过 12 个时收敛成 `(N tokens, M sentences)` 计数，不再逐个展开；
  token 较少时把文本嵌进各自的时间段里。
- 说话人显示成 `👩 female0 (female)`、`👨 …` 或 `🧑 …`，性别放在名字后的括号中。

## 标注 {id="annotations"}

`AudioEvent` 是时间轴上的基本记录：一个时间范围加一段语义。基类
[`AudioEvent`](/asr-data/api#audio-event) 用 `name` 表达音乐、噪声、静音等非语音事件；
语音是派生事件 [`Speech`](/asr-data/api#speech)，名字固定为 `speech`，并额外携带
语种、说话人和转写。

置信度属于具体事件：基类事件、[`Speech`](/asr-data/api#speech)、
[`Transcription`](/asr-data/api#transcription)、[`Sentence`](/asr-data/api#sentence)
和 [`Token`](/asr-data/api#token) 各自保存各自语义下的 `confidence`，互不覆盖。

> #### Python Example
>
> ```python
> from asr_data.annotation import AudioEvent, Speaker, Speech, Transcription
>
> end_ms = timeline.duration_ms
> speech = Speech(
>     language="zh",
>     speaker=Speaker("speaker-1"),
>     transcription=Transcription("甚至出现交易几乎停滞的情况"),
> )
> reference = timeline.annotate(0, end_ms, speech)
> music = timeline.annotate(0, end_ms, AudioEvent("music"))
> prediction = timeline.annotate(
>     0, end_ms, speech, is_reference=False, source="qwen-asr"
> )
> ```

> #### Rust Example
>
> ```rust
> use asr_data::{AudioEvent, Speaker, Speech, Timeline, Transcription};
>
> fn main() -> anyhow::Result<()> {
>     let mut timeline = Timeline::new("example-001", 1_000);
>     let speech = Speech::new()
>         .with_language("zh")
>         .with_speaker(Speaker::new("speaker-1"))
>         .with_transcription(Transcription::new("甚至出现交易几乎停滞的情况"));
>     timeline.annotate(0, 1_000, speech.clone())?;
>     timeline.annotate(0, 1_000, AudioEvent::new("music"))?;
>     timeline.annotate_with(0, 1_000, speech, false, Some("qwen-asr"))?;
>     Ok(())
> }
> ```

### 参考标注与预测标注 {id="groups"}

Timeline 将事件分成两个集合，避免真值与模型结果混在一起：

| 集合                  | `source` 规则 | 典型内容                       |
| --------------------- | ------------- | ------------------------------ |
| `timeline.reference`  | 不需要来源    | 人工标注、审核结果、数据集真值 |
| `timeline.prediction` | 必须提供来源  | ASR、说话人识别或导入流程结果  |

`reference` 和 `prediction` 都是 `list[AudioEvent]`（Rust 为 `Vec<AudioEvent>`），
直接暴露事件对象，不再有额外的 span 包装。

调用 `timeline.annotate()` 时，Reference 使用 `is_reference=True`（默认）且不接受
`source`；Prediction 使用 `is_reference=False` 并必须提供非空字符串，例如
`"whisper"`、`"qwen-asr"` 或 `"import"`。Rust 的 `annotate(start_ms, end_ms, event)`
默认写入 reference；指定 `is_reference` / `source` 时使用
`annotate_with(start_ms, end_ms, event, is_reference, source)`。不同类型的
prediction 可以来自不同模型，例如说话人分离使用 `"diarization-v2"`，转写使用
`"qwen-asr"`。

### 标注类型 {id="adding"}

| 类型       | Payload      | 用途                             |
| ---------- | ------------ | -------------------------------- |
| AudioEvent | `AudioEvent` | 基类事件，如音乐、噪声、静音     |
| Speech     | `Speech`     | 派生语音，携带语种、说话人和转写 |

语音直接传 [`Speech`](/asr-data/api#speech)，其他事件传
[`AudioEvent`](/asr-data/api#audio-event)。`annotate()` 返回写入后的事件，可以读取
`id`、`name`、`start_ms`、`end_ms`、`source` 和 `confidence`。取某个声道的波形用
`timeline.as_waveform()`，播放某个时间范围用 `timeline.display(start_ms, end_ms)`；
事件本身不再单独提供 `as_waveform()` 或 `display()`。

### 说话人、转写与 Token {id="payloads"}

[`Speech`](/asr-data/api#speech) 是语音事件，集中承载语种 `language`、说话人
`speaker` 和转写 `transcription`。语种只在语音上标注，不挂在基类事件或转写上。

[`Speaker`](/asr-data/api#speaker) 包含 `name` 和可选的 `gender`（`male` /
`female` / `unknown`）。一段语音最多一个说话人；两人同时说话时写成两段可重叠的
语音。

[`Transcription`](/asr-data/api#transcription) 包含 `text`、`sentences` 和
`confidence`。全文 `text` 是最小内容；句级 [`Sentence`](/asr-data/api#sentence)
和句内 [`Token`](/asr-data/api#token) 都是可选切分。Token 可以携带文本、绝对起止
时间和置信度，并且必须落在所属句子内。

`AudioEvent` 是扁平对象（`name`、`start_ms`、`end_ms`、`source`、`confidence`）；
`Speech` 在这之上再加 `language`、`speaker` 和 `transcription`。事件不可原地修改，
需要改名、换转写或换说话人时，删除后重新写入新事件。

> #### Python Example
>
> ```python
> # 取出某个声道当前完整的波形
> timeline_waveform = timeline.as_waveform()
> ```

> #### Rust Example
>
> ```rust
> let timeline_waveform = timeline.as_waveform()?;
> ```

### 完整校验规范 {id="validation"}

下面的规则是事件的完整有效性标准。重叠校验以单个声道的
[`Timeline`](/asr-data/api#timeline) 为边界：不同声道、reference 与 prediction
彼此独立，可以互相重叠。

#### 当前状态与删除

事件不再具有 `status`。集合中的每条事件都表示当前有效状态：修改时删除旧事件并
写入新事件，删除时从集合中移除，不使用 `partial`、`revised`、`deleted` 等逻辑状态。

#### 时间范围

- 事件范围必须满足
  `0 <= start_ms <= end_ms <= timeline.duration_ms`。
- 范围采用半开区间 `[start_ms, end_ms)`。`[0, 100)` 与 `[100, 200)` 首尾相接，
  不构成重叠。
- Rust 的 `TimeRange` 允许 `start_ms == end_ms` 的零长度范围，并且不会与其他范围重
  叠；Python `annotate()` 在入口要求 `end_ms > start_ms`。
- Python `annotate()` 会立即检查起止顺序和 timeline 边界。Rust 直接构造
  `TimeRange` 时应遵守同一标准；`Audio::validate()` 会检查事件是否超出 timeline
  结束位置。
- Python 中 Token 的 `start_ms` 和 `end_ms` 必须同时提供或同时省略。带范围的
  Token 必须完全位于所属 [`Sentence`](/asr-data/api#sentence) 内，句子必须完全
  位于所属 [`Speech`](/asr-data/api#speech) 内。

#### Reference 与 Prediction 来源

- Reference 事件不携带 source。Python 调用 `timeline.annotate()` 时使用
  `is_reference=True` 并省略 source；Rust 的 `annotate(start_ms, end_ms, event)`
  默认同样写入 reference。指定 `is_reference` / `source` 时使用 `annotate_with`。
  整体验证会拒绝通过直接修改得到的非空 reference source。
- 每条 Prediction 事件都必须有 source，而且 source 至少包含一个非空白字符。
  `""` 和 `"   "` 无效。
- source 使用原始字符串精确比较，区分大小写，不会自动 trim 或标准化。因此
  `"asr"`、`"ASR"` 和 `" asr "` 是三个不同来源。

#### 重叠规则

下表适用于 reference，也适用于 prediction 的同一个 source。表中的“允许”只表示
没有新增的重叠限制，其他范围、source 和 payload 规则仍然有效。

| 组合 | 是否允许重叠 | 分组与说明 |
| ---- | ------------ | ---------- |
| 同名基类事件 ↔ 同名基类事件 | 不允许 | 相同事件名共用一条区间轨道；不同事件名（如音乐与噪声）可以重叠。 |
| 语音 Speech ↔ 语音 Speech | 都有说话人且名字不同时允许 | 缺说话人或同名说话人时冲突；两人同时说话写成两段重叠语音。 |
| 语音 Speech ↔ 基类事件 | 允许 | 例如语音与背景音乐可以同时发生。 |

`Speech` 内部的 `Transcription`、`Sentence` 和 `Token` 不参与集合级重叠，但各自有
范围约束：句子互不重叠、句子落在语音内、token 落在句子内。同一个 prediction
source 使用上表；不同 source 可以自由重叠。例如两个声音活动检测模型可以保存彼此
重叠的结果。

#### 去重、冲突与原子性

- 内容完全相同的重复插入具有幂等性：返回已有事件，不插入第二条。比较会忽略自动
  生成的 `id`，但会比较 range、source 和包含 confidence 的完整内容（语种、说话人、
  转写）。
- 检测到冲突时会返回错误，不会自动合并、裁剪、拆分、覆盖或移动范围。
- `Timeline.relabel_prediction_source(from, to)` 会先校验改名后的完整 prediction
  集合。只要一条冲突，整个重命名失败且不修改任何事件。
- `Timeline.remove(event_id)` 按 ID 删除一条事件；`Timeline.remove_predictions(source)`
  删除某个来源的全部预测。

#### 校验发生的位置

| 入口 | 校验行为 |
| ---- | -------- |
| Python `Timeline.annotate()` | 添加前检查范围、is_reference、source 和事件重叠规则。 |
| Rust `Timeline::annotate()` / `annotate_with()` | 幂等插入，并检查 is_reference、source 与重叠规则。 |
| Python `Timeline.relabel_prediction_source()` | 先校验完整候选集合，成功后一次性提交。 |
| `Timeline.remove()` / `remove_predictions()` | 按 ID 或来源删除，不触发新的校验。 |
| `Audio.validate()` | 重新检查声道、timeline、事件边界、source 和集合重叠。 |
| 数据库读取、插入和更新 | 使用 schema v12，并通过 `Audio.validate()` 拒绝无效文档。 |

Rust 的 `reference` 和 `prediction` 是公开 `Vec`，可以绕过 `annotate()` 直接修改；
这种用法必须在持久化前调用 `Audio::validate()`。数据库写入也会自动执行同样的整
体验证。

### 评测 {id="evaluation"}

[`Timeline.eval()`](/asr-data/api#timeline-eval) 比较 reference 与 prediction。
不传参数时会自动发现所有可评测 source；也可以分别通过 `transcription` 和
`activity` 限定一个或多个来源。

> #### Python Example
>
> ```python
> timeline.annotate(
>     0, end_ms, Speech(),
>     is_reference=False, source="silero-vad"
> )
> evaluation = timeline.eval()
>
> print(evaluation.transcription["qwen-asr"].cer)
> print(evaluation.transcription["qwen-asr"].normalized_reference)
> print(evaluation.activity["silero-vad"].f1)
> print(evaluation.activity["silero-vad"].events["speech"].f1)
> ```

> #### Rust Example
>
> ```rust
> use asr_data::{Timeline, TimelineEvalConfig};
>
> fn main() -> anyhow::Result<()> {
>     let timeline = Timeline::new("example-001", 1_000);
>     let evaluation = timeline.eval(&TimelineEvalConfig::new())?;
>     println!("{}", evaluation.transcription.len());
>     Ok(())
> }
> ```

自动发现转写来源时会检查带 `transcription` 的 `Speech`；Activity 来源来自全部
prediction 事件，语音固定按 `speech` 参与，其他事件按各自的 `name`。显式参数接受
字符串或字符串列表：

> #### Python Example
>
> ```python
> selected = timeline.eval(
>     transcription=["qwen-asr", "whisper"],
>     activity="silero-vad",
> )
> ```

> #### Rust Example
>
> ```rust
> let selected = timeline.eval(
>     &TimelineEvalConfig::new()
>         .with_transcriptions(["qwen-asr", "whisper"])
>         .with_activity("silero-vad"),
> )?;
> ```

只传入其中一个参数时只评测该任务。显式来源不存在时抛出错误；完全没有可评测的
reference 和 prediction 时同样报错。

#### 转写评测

转写评测先按时间顺序组合 reference 中带转写的 `Speech`，再计算字符错误率。默认启
用内嵌中文 TN，将书写形式标准化为口语形式后去除空白和标点。例如 `"2024年"` 与
`"二零二四年"` 会被视为相同文本。FST 资源已经编译进 asr-data，不需要安装或调用外
部标准化服务。

| 字段                    | 含义                         |
| ----------------------- | ---------------------------- |
| `cer`                   | 字符错误率 `(S + D + I) / N` |
| `matches`               | 匹配字符数                   |
| `substitutions`         | 替换字符数                   |
| `deletions`             | 删除字符数                   |
| `insertions`            | 插入字符数                   |
| `precision`             | 字符级准确率                 |
| `recall`                | 字符级召回率                 |
| `f1`                    | 字符级 F1                    |
| `exact_match`           | 标准化后的文本是否完全相同   |
| `reference`             | 原始参考文本                 |
| `hypothesis`            | 原始预测文本                 |
| `normalized_reference`  | 标准化后的参考文本           |
| `normalized_hypothesis` | 标准化后的预测文本           |
| `normalization`         | `"zh_tn"` 或 `"none"`        |

如需严格按原始字符评测，可以关闭标准化：

> #### Python Example
>
> ```python
> raw = timeline.eval(transcription="qwen-asr", normalize=False)
> print(raw.transcription["qwen-asr"].cer)
> ```

> #### Rust Example
>
> ```rust
> let raw = timeline.eval(
>     &TimelineEvalConfig::new()
>         .with_transcription("qwen-asr")
>         .with_transcription_normalization(TranscriptionNormalization::None)
>         .with_traditional_to_simple(false)
>         .with_full_to_half(false)
>         .with_remove_erhua(false)
>         .with_remove_interjections(false)
>         .with_remove_puncts(false),
> )?;
> println!("{}", raw.transcription["qwen-asr"].cer());
> ```

这些中文清理选项会同时作用于 reference 和 prediction，且默认均为 `True`。如果
某个数据集需要保留对应现象，可以单独关闭：

> #### Python Example
>
> ```python
> cleaned = timeline.eval(
>     transcription="qwen-asr",
>     remove_erhua=False,
>     remove_interjections=False,
> )
> ```

> #### Rust Example
>
> ```rust
> let cleaned = timeline.eval(
>     &TimelineEvalConfig::new()
>         .with_transcription("qwen-asr")
>         .with_remove_erhua(false)
>         .with_remove_interjections(false),
> )?;
> ```

处理顺序为繁转简、中文 TN、去儿化、全角转半角、去语气词、去标点。去语气词覆盖
常见的“嗯”“啊”“呃”。这些参数也可直接传给 `AudioDB.eval_transcription()`，
用于只评测转写任务。

#### 声音活动评测

Activity 评测只使用 `annotate()` 写入的事件，不会从转写或说话人自动推断活动区间。
语音 `Speech` 固定按事件名 `speech` 参与，其他事件按各自的 `name`。reference 至少
有一条事件才表示该 timeline 已完成活动标注；没有 reference 事件的 timeline 不参
与该任务。已标注 timeline 中，事件区间之外的部分视为无活动。

评测分为两层。`evaluation.activity[source]` 会忽略事件名，把所有事件区间合并后
评测“是否存在声音活动”；`evaluation.activity[source].events[event]` 再按事件名
（`speech`、`music` 等）做 one-vs-rest 评测。纯活动检测结果可以写成不带转写和说话
人的 `Speech`，它同样参与整体和 `speech` 事件级评测。

| 字段                | 含义                               |
| ------------------- | ---------------------------------- |
| `reference_ms`      | reference 中的活动总时长           |
| `predicted_ms`      | prediction 中的活动总时长          |
| `true_positive_ms`  | 正确预测为活动的时长               |
| `true_negative_ms`  | 正确预测为无活动的时长             |
| `false_positive_ms` | 把无活动误判为活动的时长           |
| `false_negative_ms` | 漏掉的活动时长                     |
| `precision`         | 活动区间准确率                     |
| `recall`            | 活动区间召回率                     |
| `f1`                | 活动区间 F1                        |
| `iou`               | reference 与 prediction 的区间 IoU |
| `events`            | 以 event 名称为键的事件级结果      |

`TimelineEvaluation.transcription` 和 `activity` 都是以 source 为键的字典；未评测
的任务返回空字典。

#### 说话人评测

`AudioDB.eval_speaker()` 按时间评估说话人分离结果。说话人名称本身不要求一致：
每条 timeline 会先通过最优一对一映射对齐 reference 与 prediction 的说话人标签，
再累计 missed speech、false alarm 和 speaker confusion，最终计算 DER。

当前实现不使用 collar；重叠语音按同时活跃的说话人数累计 speaker-time。结果同时
提供 `coverage`、`missing_predictions` 和对应 timeline ID，便于区分模型错误与
预测缺失。

#### 数据集评测

[`evaluate_dataset()`](/asr-data/api#evaluate-dataset) 接受一组 Audio。数据库
评测按任务使用 `AudioDB.eval_transcription()`、`AudioDB.eval_activity()` 和
`AudioDB.eval_speaker()`，并自动分页读取所有匹配记录：

> #### Python Example
>
> ```python
> from asr_data import evaluate_dataset
>
> memory_result = evaluate_dataset(docs, normalize=False)
> transcription = db.eval_transcription(
>     ["qwen-asr", "whisper"],
>     metadata={"split": "test"},
> )
> activity = db.eval_activity("silero-vad", metadata={"split": "test"})
>
> print(transcription["qwen-asr"].cer)
> print(transcription["qwen-asr"].coverage)
> print(activity["silero-vad"].f1)
> print(activity["silero-vad"].events["speech"].f1)
> ```

> #### Rust Example
>
> ```rust
> let memory_result = evaluate_dataset(&docs, &TimelineEvalConfig::new())?;
> println!("{}", memory_result.transcription["qwen-asr"].cer());
> ```

数据集 CER 累加每条 timeline 的替换、删除、插入和参考字符数后计算，不会平均单条
CER，也不会把不同文档的文本拼接后对齐。Activity 的整体指标与各 event 指标都先累
加各 timeline 的 TP、TN、FP、FN 毫秒数，再计算总体 precision、recall、F1 和 IoU。

每个 source 都记录 `evaluated_timelines`、`unannotated_timelines`、
`missing_predictions`、`coverage` 和对应 ID。这样模型只覆盖部分数据时不会被误认
为完整数据集指标。

## 便捷方法 {id="helpers"}

Timeline 提供组合转写、按来源查询和批量维护等便捷方法，不需要使用者手动遍历全部
事件。

> #### Python Example
>
> ```python
> reference_text = timeline.reference_transcript
> predicted_text = timeline.prediction_transcript("qwen-asr")
> events = [event for event in timeline.prediction if event.source == "qwen-asr"]
>
> print(reference_text.text)
> print(predicted_text.text)
> print(predicted_text.language, len(events))
> timeline.relabel_prediction_source("whisper", "whisper-large-v3")
> timeline.remove_predictions("qwen-asr")
> audio.validate()
> ```

> #### Rust Example
>
> ```rust
> use asr_data::{Audio, AudioSource};
>
> fn main() -> anyhow::Result<()> {
>     let audio = Audio::with_id(
>         "example-001",
>         AudioSource::from_url("https://deepasset.oss-cn-beijing.aliyuncs.com/example.wav"),
>     )?;
>     for timeline in audio.timelines().values() {
>         println!("{} events", timeline.span_count());
>     }
>     audio.validate()?;
>     Ok(())
> }
> ```

| 方法                                  | 作用                              |
| ------------------------------------- | --------------------------------- |
| `reference`                           | 参考事件列表，`list[AudioEvent]`   |
| `prediction`                          | 预测事件列表，`list[AudioEvent]`   |
| `reference_transcript`                | 组合参考中的转写                  |
| `prediction_transcript(source)`       | 只组合指定来源的转写              |
| `remove_predictions(source)`          | 删除指定来源的全部 prediction     |
| `relabel_prediction_source(from, to)` | 批量重命名预测来源                |
| `remove(event_id)`                    | 按 ID 删除一条事件                |
| `annotate(...)`                       | 写入参考或预测事件                |
| `audio.validate()`                    | 检查音频、时间轴、范围和来源约束  |

`reference` 和 `prediction` 直接返回事件对象。需要某个来源的预测时用列表推导按
`event.source` 过滤，或先用 `prediction_transcript(source)` 只取转写。Timeline 不
再提供 `transcriptions`、`activities`、`speakers` 等顶层类型属性；转写、句子、
token、语种和说话人都从事件上读取。

`reference_transcript` 和 `prediction_transcript(source)` 会把带转写的 `Speech`
按开始时间组合为 [`Transcript`](/asr-data/api#transcript)，语种取第一段带转写的语
音。基类事件没有文字，不参与组合。

Prediction 的 `prediction_transcript()` 必须指定 source，防止混合不同模型的输出。
`relabel_prediction_source()` 适合统一历史模型名称，`remove_predictions()` 适合清
理一次错误推理产生的全部结果。写入数据库前可以调用 `audio.validate()` 做一次完整
校验。
